# Chapter 8: RAG 检索增强生成与工具集成

## RAG 基本概念

RAG（Retrieval Augmented Generation）是一种将检索和生成结合的技术，用于增强 LLM 的答案质量。

## RAG 完整流程

### 1. 文档加载（Document Loading）
- 从知识库目录读取各类文档（.md, .txt 等）
- 支持多文件格式
- 保留文档源信息用于追溯

### 2. 文本切分（Chunking）
- 将长文档按段落分割成更小的 chunks
- 每个 chunk 是一个独立的检索单位
- 保持 chunk 的语义完整性
- 保存每个 chunk 的源文件信息

### 3. 向量化与索引（Vectorization & Indexing）
- 将 chunks 转换为向量表示
- 使用向量数据库（如 Qdrant）存储
- 建立快速检索索引

### 4. 检索（Retrieval）
查询流程：
- 将用户问题转换为向量
- 在向量空间中计算相似度
- 返回 top-k 最相似的 chunks

### 5. 上下文构建（Context Building）
- 将检索到的 chunks 组织成上下文
- 按相关性排序
- 组合成完整的背景信息

### 6. 答案生成（Answer Generation）
- LLM 基于原始问题 + 检索的上下文生成答案
- 确保答案有知识库支持
- 减少幻觉（hallucination）

## RAGTool 实现细节

### 核心参数
- `knowledge_dir`：知识库目录路径
- `top_k`：返回的相似文档数量（默认3）
- `min_score`：相似度阈值，过滤低相关性结果

### 评分机制
当前实现使用字符匹配计数评分：
```
score = 查询中在内容中出现的字符数
```

这是一个简单的基于词汇的相似度计算，存在以下特点：
- 优点：快速，无需复杂计算
- 缺点：不理解语义，容易误匹配
- 需要比较高的 min_score 来过滤低相关性结果

### 返回格式
每个检索结果包含三个关键字段：
- `score`：相似度分数，值越高说明相关性越强
- `source`：文档来源（文件名），便于溯源
- `content`：实际内容，是问题相关的文本片段

## RAG 优势与限制

### 优势
1. **减少幻觉**：答案基于实际知识库
2. **提高准确性**：使用领域专有知识
3. **可追溯性**：知道答案来自哪个文档
4. **及时更新**：无需重新训练模型

### 当前限制
1. 检索质量依赖评分函数
2. 长文档可能切分不当导致上下文丢失
3. 不支持跨文档的复杂推理
4. 向量化方法影响检索精度

## RAG 系统评估指标

### 检索精度（Retrieval Recall）
- 能否找到答案相关的 chunks？
- 是否有无关 chunks 混入？

### 答案质量（Answer Quality）
- 基于检索的上下文能否生成正确答案？
- 答案的完整性和准确性

### 用户体验
- 响应速度
- 结果的可信度和可解释性
