# Chapter 7: Agent 核心架构与工具系统

## ReActAgent 核心循环

ReActAgent（Reasoning + Acting）是结合推理与行动的智能体架构，其核心循环包含以下步骤：

### Thought（思考）
Agent 首先分析用户问题，进行逻辑推理，拆解任务，规划下一步行动。

### Action（行动）
基于思考结果，Agent 决定采取的行动，通常是调用一个特定的工具。行动格式为：`[工具名:参数]`

### Observation（观察）
工具执行后返回结果，Agent 观察这个结果，判断是否需要继续循环。

### 循环条件
- 达到最大迭代次数时停止
- 当获得充分信息可以给出最终答案时停止
- 当工具执行失败或返回错误时可能需要重试

## SimpleAgent 实现

SimpleAgent 是基础的智能体实现，具有以下特点：

- 维护对话历史，支持多轮对话
- 系统提示词定制化
- 工具注册与调用机制
- 工具调用格式：`[TOOL_CALL:工具名:参数]`
- 最大迭代次数限制（默认5次）
- 支持单一工具顺序调用，不支持并行调用

### 工作流程
1. 构建消息列表（系统提示 + 历史消息 + 用户输入）
2. 调用 LLM 获取响应
3. 解析响应中的工具调用
4. 如果有工具调用，则执行工具，将结果作为新消息继续循环
5. 直到没有工具调用或达到最大迭代次数

## ToolRegistry 工具注册表

ToolRegistry 是工具管理的核心组件，提供：

### 主要功能
- **工具注册**：通过 `register()` 方法注册新工具
- **按名称查找**：快速定位指定工具
- **统一执行**：调用 `execute()` 方法执行工具
- **工具描述**：通过 `get_tools_description()` 生成可被 LLM 理解的工具列表

### 工具接口
每个工具都应实现 BaseTool 基类：
- `name`：工具唯一标识
- `description`：工具功能描述
- `run(tool_input)`：工具执行方法

实现自定义工具的步骤：
1. 创建类继承 BaseTool
2. 定义 name 和 description 属性
3. 实现 run() 方法处理具体逻辑
4. 通过 registry.register() 注册工具

### 工具执行流程
1. 验证工具是否存在
2. 获取工具对象
3. 调用工具的 `run()` 方法
4. 返回执行结果

## Agent 与工具的交互

### 消息格式
Agent 与 LLM 通过结构化消息交互：
- `system`：系统提示，定义 Agent 角色和能力
- `assistant`：模型输出
- `user`：用户输入或工具执行结果

### 工具信息集成
系统提示中包含：
- 可用工具列表及其功能说明
- 工具调用格式规范
- 工具使用示例

### 工具调用格式
标准格式：`[TOOL_CALL:工具名:参数]`

Agent 解析这个格式并提取：
- 工具名称
- 工具参数

### 错误处理
- 工具执行失败时返回错误信息
- Agent 可基于错误信息进行重试或替代方案
- 超过最大迭代次数时返回超时结果
